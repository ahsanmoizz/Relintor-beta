# Relintor Beta UX observation checklist

Use one copy of this block for each screen or important state. Observe without coaching first.

```text
SCREEN / STATE:
USER GOAL:
EXPECTED PRIMARY ACTION:
DID USER FIND IT WITHOUT HELP? YES / NO
CONFUSION:
UNEXPECTED WAIT:
BAD WORDING:
VISUAL DEFECT / OVERFLOW:
SYSTEM FEEDBACK AFTER ACTION:
EXTERNAL EXPLANATIONS REQUIRED (COUNT):
SEVERITY: P0 / P1 / P2 / P3
NOTES:
```

## Journey result

```text
PROJECT TYPE: NEW IDEA / TAKEOVER
COMPLETED WITHOUT SUPPORT? YES / NO
RAW ERROR SHOWN? YES / NO
AMBIGUOUS PRIMARY ACTION? YES / NO
MANUAL REFRESH REQUIRED? YES / NO
TECHNICAL ID OR EXTENDED PATH LEAK? YES / NO
EXECUTION CONFUSED WITH VERIFICATION? YES / NO
RECOVERY DECISION UNDERSTOOD? YES / NO / NOT ENCOUNTERED
TOTAL EXTERNAL EXPLANATIONS:
TOP THREE FOLLOW-UPS:
```

Do not mark the journey successful merely because the underlying commands passed. A successful Beta journey lets the user explain what is happening, what Relintor needs next, and why completion has or has not been proven.
